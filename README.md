## 📌 Purpose of the Project

Banks lose money when a customer who is about to default or commit fraud is **not noticed in time**. Reviewing every account by hand is impossible, so this project builds a machine-learning model that scores each customer and raises an alert:

| Output | Meaning |
|--------|---------|
| **Low Risk (0)** | Normal customer, no action needed |
| **High Risk (1)** | Needs a manual review by the risk team |

The app also shows the **high-risk probability**, so analysts can review the most doubtful customers first.

**Why this matters (business logic)**
- **Missing a risky customer (False Negative / Type-II error)** = real financial loss → the *costly* mistake.
- **Flagging a safe customer (False Positive / Type-I error)** = an extra review → the *cheap* mistake.
- Therefore the final model was chosen by **Recall / F2-score** (recall-weighted), not by accuracy alone.

---

## 🧠 What the Project Does

1. Takes **16 customer inputs** (age, income, credit score, missed payments, debt, etc.).
2. Cleans the data (KNN imputation, scaling, one-hot encoding) automatically inside one saved pipeline.
3. Predicts **Low / High risk** and the **probability** of high risk.
4. Shows a verdict card, probability gauge, key metrics, rule-of-thumb risk signals, and a **downloadable CSV report**.

| Item | Value |
|------|-------|

| Customers | 4,600 |

| Target | `risk_status` (0 = Low Risk, 1 = High Risk) |
| Class balance | 4,043 low risk (87.9%) vs **557 high risk (12.1%)** → imbalanced |
| Dropped columns | `customer_id`, `last_transaction_date` (no predictive signal) |
| Missing values | 7 features, 2.1%–4.9% each → filled with KNN / most-frequent imputation |
| Split | 80% train (3,680) / 20% test (920), stratified |

## 🏆 Final Model

**Logistic Regression + Random Over-Sampling**, inside one pipeline: `KNN imputer → scaler → one-hot encoder → over-sampler → Logistic Regression`.

| Metric (test set) | Score |
|-------------------|-------|
| Accuracy | 99.78% |
| Precision | 98.23% |
| **Recall** | **100%** (0 missed high-risk customers) |
| F1-score | 0.9911 |
| F2-score | 0.9964 |
| AUC-ROC | 1.000 |
| Confusion matrix | 807 TN · 2 FP · 0 FN · 111 TP |

Saved at `model/risk_alert_pipeline.pkl` (metrics in `model/metrics.json`).

> ⚠️ Scores are near-perfect, which suggests clean (possibly synthetic) data. Validate on fresh real-world data before relying on them in production.

### 1. Missing Values per Feature (Train Set)
![Missing Values per Feature](charts/Missing%20Values%20per%20Feature%20%28Train%20Set%29.png)

**Address:** `charts/Missing Values per Feature (Train Set).png`

**Interpretation:** Seven features have gaps, from 2.1% (`region`) up to 4.9% (`credit_score`). The gaps are small but spread over many columns, so deleting rows would waste data. KNN imputation (numeric) and most-frequent imputation (categorical) were used instead. After imputing, the feature means barely moved (e.g. `credit_score` 677.60 → 677.64), so the distributions were not distorted.

---

### 2. Confusion Matrix – Logistic Regression (Baseline)
![Confusion Matrix Baseline](charts/Confusion%20Matrix%20-%20Logistic%20Regression%20%28Baseline%29.png)

**Address:** `charts/Confusion Matrix - Logistic Regression (Baseline).png`

**Interpretation:** 809 low-risk and 111 high-risk customers were all classified correctly (0 Type-I, 0 Type-II errors). This means the two risk classes are almost linearly separable in this dataset, which is why a simple linear model works so well.

**Interpretation:** The single deep tree misses **11** high-risk customers (False Negatives) and raises **9** false alarms, giving only ~90.1% recall. Missing 11 risky customers is exactly the costly mistake, so this model is not suitable as the final choice.

### 5. Decision Tree – Top 3 Levels
![Decision Tree Top 3 Levels](charts/Decision%20Tree%20-%20Top%203%20Levels.png)

**Address:** `charts/Decision Tree - Top 3 Levels.png`

**Interpretation:** Shows how the tree makes its first decisions. It splits first on `avg_late_payment_days`, then on `missed_payments_12m`, `credit_score` and `credit_utilization_ratio`. Customers who pay late for longer and have more missed payments fall into the **High Risk** (blue) branches; punctual customers fall into **Low Risk** (orange). The model relies on repayment behaviour, which is what a credit-risk model should use. *(Values shown are scaled, and the tree was trained on the balanced training set.)*

---

### 6. Decision Tree – Train vs Test F2 as Depth Increases (Overfitting Check)
![Decision Tree Overfitting Check](charts/Decision%20Tree%20-%20Train%20vs%20Test%20F2%20as%20Depth%20Increases%20%28Overfitting%20Check%29.png)

**Address:** `charts/Decision Tree - Train vs Test F2 as Depth Increases (Overfitting Check).png`

**Interpretation:** Train F2 keeps rising to 1.0 as the tree gets deeper, but test F2 peaks near **depth 6 (≈ 0.94)** and then falls to ≈ 0.90. The growing gap is classic **overfitting**: a deep tree memorises the training data instead of learning the general pattern.

---

### 7. Random Forest – Top 10 Important Features
![Random Forest Feature Importance](charts/Random%20Forest%20-%20Top%2010%20Important%20Features.png)

**Address:** `charts/Random Forest - Top 10 Important Features.png`

**Interpretation:** The strongest drivers of risk are `avg_late_payment_days` (~0.31), `missed_payments_12m` (~0.17), `credit_score` (~0.13) and `credit_utilization_ratio` (~0.12). Next come `cash_advance_count_6m` and `failed_login_attempts_3m`. Payment behaviour matters far more than spending or income, so a bank can focus monitoring on late and missed payments.

---

### 8. Tuned vs Untuned Models (Test Set)
![Tuned vs Untuned](charts/Tuned%20vs%20Untuned%20Models%20%28Test%20Set%29.png)

**Address:** `charts/Tuned vs Untuned Models (Test Set).png`

**Interpretation:** Hyper-parameter tuning (scored on F2) helps both tree families. Decision Tree: recall 0.901 → 0.964, missed customers 11 → 4 (but false alarms 9 → 21). Random Forest: recall reaches 1.000 with 0 missed customers (false alarms 1 → 5). Tuning deliberately trades some precision for fewer missed high-risk customers. Grid-tuned and randomized forests perform the same.

---

### 9. ROC Curves
![ROC Curves](charts/ROC%20Curves.png)

**Address:** `charts/ROC Curves.png`

**Interpretation:** A curve hugging the top-left corner means high True Positive Rate at very low False Positive Rate. All Logistic Regression variants and all Random Forests sit in the corner (AUC ≈ 1.0). Only the Decision Trees fall behind (AUC 0.945 untuned, 0.985 tuned). The zoomed right panel shows their curves bending away at 1–4% false-positive rate. The dashed diagonal is random guessing (AUC 0.5).

---

### 10. AUC-ROC Comparison of All Models
![AUC-ROC Comparison](charts/AUC-ROC%20Comparison%20of%20All%20Models.png)

**Address:** `charts/AUC-ROC Comparison of All Models.png`

**Interpretation:** Five Logistic Regression models and the forests score AUC ≈ 1.000, the tuned Decision Tree 0.985 and the untuned one 0.945. Because the top models are tied, AUC cannot pick the winner. The final model was therefore chosen by **cross-validated F2** (recall-weighted), where **Logistic Regression + Over-Sampling** came first (CV F2 0.9799, CV recall 98.7%).
